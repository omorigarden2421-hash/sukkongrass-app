# 引き継ぎ：品種マスターの組み直し（2026-11-12）

Claude Code でこの作業を続けるための指示書。最初にこの文書と
`claude/品種情報の出典ルール.md`（v1.2）を読むこと。

## 0. 目的
品種マスター（916品種×70列）は通販サイトのあらゆるデータの元になっているが、誤りが多い。
**今の値を直すのではなく、出典のある値だけでマスターを組み直す。**

## 1. 誤りが止まらなかった原因（2026-11-12 調査）
1. 特徴・花時期・花色・日照条件は、過去の検証で一度も対象になっていない。
2. 一次情報でない根拠で書き換えている（耐潮性は一次情報が901件中324件、成株シルエットは約半数が Gardenia.net などの販売・まとめサイト）。
3. Webを見ずにAIの推論で値を変えた回がある（GitHubの `*_noweb再検証_*` 計約60件。属からの類推）。
4. 品種の値を種の値で代用している。学名に品種名が無く別品種と同じ学名の組が6組（アケボノフウロ'ローズ'と var. striatum、フウチソウ緑葉とベニフウチソウ、ベルゲニア原種と'ニューウィンターフラワリング'、ビンカ2件、タイム2件、アメリカヅタ2件）。

**→ GitHub の過去の検証成果物（修正ログ・監査CSV・レポート）は根拠にしない。**

## 2. 大森さんの決定（2026-11-12）
| 項目 | 決定 |
|---|---|
| 照合する列 | お客様に見せる基本項目：**学名・高さ(cm)・広がり(cm)・花時期・花色・日照条件・耐暑性・常緑性**。他の事実列はその後 |
| 耐寒性 | **マスター通りでよい。照合しない**（段階とUSDAゾーンの対応は問わない） |
| 確認できない値 | **通販サイトには表示しない（空欄）** |
| 順番 | **属ごとに五十音順で全916品種**（アイリスから） |
| 文章・タグ類 | 特徴・キャッチ・おすすめ文・タグは、確定した値から作り直す。今の文章は使わない |

## 3. 基になるマスター
- **大森さんの最新版：「宿根草マスター（11/8版）」xlsx**（Sheet1、917行×70列）。claude.ai のチャットに添付されたもの。Claude Code では大森さんに置いてもらう。
- GitHub `omorigarden2421-hash/sukkongrass-app` ブランチ `claude/perennial-master-data-validation-aqs8jv` の `data-validation/_autopilot/master_working_latest.xlsx` は**古い**（11/8版と在庫数・用途区分・耐潮性・タグ類が異なる）。使わない。

## 4. 出典台帳（ledger.csv）の決まり
品種×項目ごとに1行。**マスターの値は台帳から自動で作る。マスターを手で書き換えない。**

| 列 | 中身 |
|---|---|
| 商品番号 | マスターの商品番号 |
| 植物名 / 学名 | 照合した品種（学名は出典での正式名） |
| 項目 | 学名・高さ(cm)・広がり(cm)・花時期・花色・日照条件・耐暑性・常緑性 のどれか |
| 値 | マスターに入れる値（マスターの書式に合わせる。高さは「60～90」の形） |
| 区分 | C＝一次情報／B＝大森さんが確認 |
| 出典名 / URL | Cは必須。Bは「大森さん確認 2026-xx-xx」 |
| 原文抜粋 | 出典の該当箇所（短く、15語未満） |
| 換算前の値 | フィート→cm などをしたときの元の値 |
| 確認日 | YYYY-MM-DD |
| メモ | 食い違い・名前の別名など |

### 守ること
- C は出典ルール v1.2 の一次情報だけ（MBG、RHS、州立大学 Extension、Lady Bird Johnson、USDA PLANTS、YList、育成元の公式）。**販売店・まとめサイト・Wikipedia・AIの知識は不可。**
- **品種の値は品種の出典から。** 種や属の値を品種に当てはめない。
- 実際にページを開いて（WebFetch）確かめた値だけを書く。検索結果の抜粋だけで書かない。
- **出典として使えるサイトは `build_master.py` の一覧（ALLOWED）に固定してある。** MBG、RHS、NCSU Plant Toolbox、Lady Bird Johnson、USDA PLANTS、YList、農研機構、農水省品種登録、米国植物特許、extension.〇〇.edu。これ以外のURLの行があると、マスターは作られず止まる。
- 一覧に無い大学（例：canr.msu.edu）を使いたいときは、**勝手に一覧に足さない。** 大森さんに「どのサイトを、どの品種の何に使うか」を見せて承認をもらい、`追加承認_出典ドメイン.txt` に承認日と一緒に書く。
- **育成元の公式サイト（苗を販売もしている会社を含む。Walters Gardens など）は、全品種の照合が終わってから大森さんがまとめて判断する（2026-11-12 決定）。** 途中で一件ずつ伺わない。
  - それまでは台帳に書かず、その項目は空欄（未確認）のままにする。
  - 代わりに `育成元_保留リスト.csv`（商品番号／植物名／学名／項目／候補の値／会社名／URL／メモ）に記録しておく。値はページを開いて確かめたものだけ。
  - 最後に、このリストを会社ごとにまとめて大森さんに見せる。
- 調べる途中で販売店などのページが目に入っても、そこから値を写さない。一次情報のページで同じ値を確かめられたときだけ書く。
- 見つからなければ書かない（空欄＝未確認）。必要なら「大森さんへの確認リスト」に載せる。
- 一次情報同士が食い違うときは書かず、確認リストへ。
- 花時期は出典の時期（本州・英米の気候）。十勝での時期は B として大森さんに確認。

## 5. 道具（プロジェクト文書 `claude/品種マスター組み直しキット/`）
- `build_master.py`：元マスター＋台帳 → 新マスター（未確認は空欄）＋「食い違い」「照合状況」「出典台帳」シート。URLの無いC行があると止まる。
- `check_master.py`：機械チェック（学名の重複、品種名の抜け、草丈・広がりの書式、花時期の空欄）。11/8版での結果：広がり書式78、高さ書式71、花時期空26、学名重複12行、品種名抜け6。

## 6. 進め方
1. 属を五十音順に並べ（学名の属で束ね、カタカナ名で並べる。236属前後）、1属ずつ進める。
2. 1属終わるごとに台帳を保存し、`build_master.py` で食い違いを出す。
3. 数属ごとに大森さんへ「食い違い一覧」と「確認リスト（Bにしたいもの・名前が不明なもの）」を出す。
4. 台帳とキットは GitHub かプロジェクト文書に保存して、作業が途切れても再開できるようにする。
5. 照合が一通り済んだ属から、通販サイトの商品説明の作り直しに進む（公開前に大森さんの了承）。
